# 早餐券时段交集求解器

## 这个 Skill 解决的真问题

麦当劳的早餐券设计是**故意错位**的：

- 早餐套餐券 05:00–10:29（10:29 截止）
- 麦旋风买一送一 10:00–22:00（10:00 才开卖）
- 冰美式 全天

**两张券的有效时段只重叠 29 分钟（10:00–10:29）。** 错过这 29 分钟，至少一张券作废。这件事用户自己**算不清楚**——券多的时候心算必错。

本技能求多张券时间窗口的交集，给出「几点到几点之间去能用上 N 张券」的明确答案。

## 何时用

- 「我明天早上能吃什么」
- 「这几张券能不能一起用」
- 「几点去能用上最多券」
- 「我固定吃的那套今天配不配得上」
- 任何涉及多张券 + 时间窗口的场景

**不适用**：单张券何时到期（用 `mcd-coupon-triage`）；具体下单（用 `mcd-meal-compare` 或 `create-order`）。

## 执行流程

### Step 1 · 拉卡包 + 服务端时间

`query-my-coupons` 取卡包。**必须** 同时调 `now-time-info` 确认服务端时间——券的有效期是服务端时区，别用本地时间推断。

### Step 2 · 过滤出"当日有效"券

对每张券，判断：

1. 有效期整体区间覆盖今天（开始 ≤ 今天 ≤ 结束）
2. 周几限制匹配（部分券限"周一、二、三、四、五"或"周日"）

**只保留今天能用的券。** 昨天作废的、明天才解锁的，一律剔除。

### Step 3 · 解析每张券的"当日时间窗口"

券文本里的时间信息有三种形态，都要处理：

| 形态 | 例子 | 当日窗口 |
|---|---|---|
| 全天 | `2026-10-10 00:00-2026-10-16 23:59` | 00:00–23:59 |
| 带日窗口 | `2026-10-11 05:00-2026-10-11 10:29 周日 05:00-10:29` | 05:00–10:29 |
| 跨日窗口 | `2026-10-05 00:00-2026-10-11 23:59 10:00-22:00` | 10:00–22:00（每天） |

**关键**：第二种和第三种的区别——前者窗口只在那一天，后者窗口每天重复。**解析错会把昨天作废的券当成今天能用。**

### Step 4 · 求交集（脚本完成）

把每张券的当日窗口 `[start_i, end_i]` 求：

```
intersection_start = max(start_1, start_2, ..., start_n)
intersection_end   = min(end_1,   end_2,   ..., end_n)
```

- `intersection_start < intersection_end` → **存在交集**，这段时间内所有券都能用
- 否则 → **无交集**，输出"哪几张能叠、哪几张必须分开点"

### Step 5 · 输出行动卡

格式：

```
今天能用 N 张券，最大叠加窗口：10:00–10:29（29 分钟）

| 券 | 窗口 | 价格 |
|---|---|---|
| 厚松饼套餐 | 05:00–10:29 | ¥29.9 |
| 麦旋风×2 | 10:00–22:00 | ¥15 |
| 冰美式 | 全天 | ¥9.9 |

建议：10:20 前到店（留 9 分钟缓冲）
最晚出门时间：10:10（按 10 分钟路程估）

如果起晚了：
· 10:29 后 → 厚松饼套餐作废，剩 2 张（¥24.9）
· 11:00 后 → 只剩冰美式
```

要点：
- **第一行就是答案**——窗口和时长
- **明确缓冲**：建议比窗口结束早 5–10 分钟到，别贴边
- **给出"起晚了"的降级方案**——用户要知道错过窗口后剩什么

## 三条铁律

### 1. 不替用户判断"起不起得来"

时段交集是事实陈述。"05:00–10:29" 是窗口，不是建议。**用户起不起得来是他自己的事**，Skill 只告诉"几点到能用上"。

### 2. 麦旋风买一送一这种券要看清"开始时间"

很多买一送一券 10:00 才开卖，**和早餐券窗口是错位的**。如果只看结束时间（22:00）会以为"全天都能用"，实际错过 10:00 前的 5 小时。**开始时间必须单独解析。**

### 3. 券叠加 ≠ 订单叠加

时段交集告诉你"这三张券在 10:00–10:29 都有效"，**但不保证一单能同时用三张券**。麦当劳常见规则是"同类券不叠加、不同类可叠加"，但这是常识不是实测。

**叠加规则只能用 `calculate-price` 实测**——同一单里 items 各自带 couponId，看返回的优惠明细。**当前 `calculate-price` 的 items 参数有类型校验问题，无法稳定调用，所以叠加规则暂时验不了。** 这是个已知缺口，不要假装能验。

## 脚本

`scripts/window_intersect.py` — 纯标准库，时间窗口求交集。

```bash
python scripts/window_intersect.py --input coupons.txt --date 2026-10-11
```

输入 `query-my-coupons` 的原始文本输出。脚本解析每张券的当日窗口，过滤"今天有效"的券，求交集，输出行动卡。

**为什么用脚本**：3 张以上券的窗口交集手算必错。券多时（实测 16 张），人工判断"哪几张今天能用、几张能叠"超过 5 分钟，且容易漏掉周几限制。

## 与其他 Skill 的边界

| Skill | 视角 | 解决什么 |
|---|---|---|
| `mcd-coupon-triage` | 资产 | 我有几张券、几张要过期、价值多少 |
| **mcd-morning-routine** | 行动 | 我今天能吃到啥、几点去能用上最多 |
| `mcd-meal-compare` | 比价 | 同套搭配在不同店多少钱 |
| `mcd-meal-compare` | 下单 | 帮我点这个 |

**调用顺序建议**：triage 先扫资产 → morning-routine 算今天能吃什么 → compare 比价 → create-order 下单。

## 已知缺口

- **券叠加规则未实测**：`calculate-price` 的 items 数组参数当前报类型错误，无法验证多券是否能在同一单叠加。临时方案：分开结算，每张券独立用，损失最多是少叠一张。
- **"周几限制"解析依赖文本格式**：脚本用正则匹配"周一/周二/.../周日"和"周一、二、三、四、五"，遇到非标准写法会漏。漏判时保守归入"今天可能不能用"，让用户确认。
- **跨日券的"每天窗口"假设**：如果一张券有效期跨多天且带日窗口（如 10-05 至 10-11 每天 10:00-22:00），脚本假设窗口每天重复。**这是合理假设但非保证**，券细则可能有例外。
