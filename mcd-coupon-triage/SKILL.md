# 临期券调度员

麦当劳券的核心问题不是「有多少张」，而是**结构性地用不完**。券按日解锁、按渠道锁定、早餐券只有 05:00–10:29 有效。不做调度的结果是：每月白白作废一批。

**核心等式：券的价值 = 名义金额 × 你实际会在有效期内用掉的概率。** 本技能算的是右边那个数。

## 何时用

- 「我有什么券」「看看我的券」「券要过期了吗」
- 「怎么把券花掉」「帮我省钱」
- 券包里出现「今日到期」「本周到期」标签
- 用户明确要省钱、要凑单、要搭配

**不适用**：单笔订单的优惠叠加计算（直接走 `calculate-price` 的 `couponId`）；用户已经在具体下单流程中（不要打断）。

## 执行流程

### 第 0 步：拉取钱包

调用 `query-my-coupons`（默认参数即可，14 张左右一页装得下）。

同时并行调用 `now-time-info` 确认当前时间——**券的紧迫度必须以服务端时间为准**，不要凭上下文里的日期推断。

### 第 1 步：算紧迫度，不要只列券

把原始输出存成文本，交给脚本：

```bash
python scripts/triage.py --input coupons.txt --now "2026-10-09 15:24"
```

脚本负责确定性计算（避免心算错），产出三档分桶 + 一个附加标记：

| 桶 | 判据 | 处置 |
|---|---|---|
| **P0 今日作废** | 有效期内剩余 < 12 小时 | 立刻提醒，给出可用的门店+商品组合 |
| **P1 本周内作废** | 剩余 ≤ 7 天 | 排进逐日行动表 |
| **P3 安全垫** | 剩余 > 7 天 | 只统计总额，不打扰 |

外加一个**「需早起」标记**：有效期窗口在早晨（05:00–10:29）的券会被标出来，但**仍归入 P1/P3，不单独成桶**。

**为什么不给「结构上用不掉」下判断**：券能不能用取决于用户作息，脚本不知道。把它归进「建议放弃」是对用户生活方式的臆测——周六早上完全可以吃掉一张早餐券。所以只陈述事实（这券只在早上有效），取舍交给用户。这条是硬约束，不要改。

### 第 2 步：给行动，不给清单

按这个结构回复，**先说作废金额，再说行动**：

```
今晚作废：¥19.8（2 张，23:59 截止）
本周内：¥109.3（7 张，其中全部需早起）
安全垫：¥89.5（5 张，下周才解锁）

建议动作：
1. 今晚 23:59 前 —— 麦旋风任选 + 薯薯任选，各 ¥9.9，可外送
2. 10-10 至 10-16 —— 每天早晨窗口各一张，7 张合计 ¥109.3
3. 10-17 起 —— 周末套餐陆续解锁，不急
```

要点：
- **金额一律先加总再开口**。逐张念一遍是废话，用户要的是「我该损失多少」。
- **标注时段约束，但不劝放弃**。说「这 7 张只在 05:00–10:29 有效」，不要说「建议放弃」。
- 每条动作必须带**时段和渠道**，这是麦当劳券能不能落地的唯一约束。

### 第 3 步：能接就接上

用户说「那现在帮我点」→ 直接进入下单链路，不要重新走一遍分析：

1. `query-nearby-stores`（beType=1 到店自提）或 `delivery-query-stores`（外送）
2. `query-meals` 拿商品列表
3. `query-meal-detail` 拿特制项（传了 couponId 才不会报错）
4. `calculate-price` 试算，**带 couponId**
5. 展示总价 → 确认 → `create-order`

券ID 从第 0 步的 `query-my-coupons` 输出里取。

## 脚本

`scripts/triage.py` — 纯标准库，无依赖。

```bash
python scripts/triage.py --input coupons.txt [--now "YYYY-MM-DD HH:MM"]
```

读取 `query-my-coupons` 的原始文本输出（整段粘贴即可），解析出每张券的名称、金额、有效期、标签，按上述四桶分类并汇总。

**为什么用脚本**：券多的时候（实测14 张）心算总额极易出错，而这个数字直接决定用户的钱。确定性计算交给代码。

## 边界

- 只做**券的调度与止损**。不替用户决定吃什么，不做营养搭配，不推荐新品——那些是另外的场景。
- 门店可用性以 `query-store-coupons` 为准。卡包里的券不代表任何一家门店都能用。
- 金额单位：接口返回**分**，展示除以 100。
- 不代替用户确认下单。任何写操作前必须拿到明确确认。
